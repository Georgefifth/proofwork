## 视觉与首次使用观察

已实际查看桌面结果、帮助、作者表单、移动端结果/表单、空状态、加载、网络错误、损坏 JSON 与剪贴板错误截图。检查了文字层级、按钮状态、证据框、换行、整页溢出和恢复提示。

- 桌面可同时看来源和差异；预期值与候选值、失败理由、Locate source 入口清楚，能够从结果继续核对来源。
- 初次进入直接看到两个合成错误，有明确 demo 标记及 Use your own PDF 入口。帮助在产品内解释五个阶段。用户仍需已有 Markdown/HTML 提取输出；本工具不会替用户做 OCR。
- 创建事实需要证据选区、行列值、人工确认与保存。单元格预填可以替代四个字段的手动输入，但对 PDF 的人工核对仍是必要步骤。
- 390/320px 能保存、比较和导出，没有整页横向溢出；来源与结果垂直堆叠，使结果位于 PDF 下方。320px 的 PDF 表格文字较小，核对时应使用已验证的缩放。
- 表单与 PDF 有独立滚动区；截图只显示当前内部滚动位置，不代表全部表单内容同时可见。测试实际滚动/聚焦后完成了任务，但嵌套滚动提高了使用成本。
- 加载提示为浮动状态，暂时覆盖底部附近的禁用操作区域；等待后消失，未阻碍继续操作。

## 尚未解决的限制与建议

1. **P2 体验改进候选：移动端滚动成本。** 来源、表单与结果距离较远；建议评估“跳到结果”或来源折叠入口，并用同一任务比较滚动和定位次数。尚未实现，也未证明这种改法更好。
2. **P3 文案：单条结果的 summary 仍显示 “1 verified checks / 1 new regressions”。** 不改变结果含义，后续可整理单复数文案。
3. 保存是主动选择的设备草稿或导出；未保存工作在完整重载后不会保留。草稿不保存 PDF，恢复后须重新附匹配文件。测试已验证这个约束，不应承诺自动永久保存。
4. 应用内三个视图不是浏览器历史路由；Back 测试仅验证实际返回后的项目状态，不证明 Back 会依次返回 Source / Outputs / Review。
5. 仅验证合成的两页 PDF 和有限表格异常；未覆盖真实大文件性能、加密 PDF、存储配额耗尽、多标签写入竞争、真实设备触摸、OS 权限弹窗、其他浏览器或屏幕阅读器。模拟拒绝不代表全部真实权限路径已测。
6. 表格序号需要保持稳定，嵌套表和重复标签会进入审核；通过检查只保护已保存事实，不是整份文档准确性认证。

未解决项目没有被计作已执行场景的 Blocked；它们是覆盖范围外或非阻断的体验/产品限制。
